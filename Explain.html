How SkyAutoMusic Works: Overview

SkyAutoMusic is a Python-based auto-player that reads song files and converts them into keystrokes that play music in Sky: Children of the Light. Here's how the entire system works:

1. Initialization and Setup

When you start the application, it:

  • Imports Dependencies - The program starts by importing key libraries: json (for parsing song files), time (for timing playback), keyboard (for detecting key presses), ahk (for sending keystrokes), threading (for running background tasks), and os (for file operations).
  • Creates AHK Interface - Initializes the AutoHotkey interface with ahk_script = ahk.AHK() which will handle all the keyboard input simulation.
  • Sets Up Global Variables - Creates flags like playing_song and stop_current_song to track program state.

2. Background Thread for Key Monitoring

The program starts a dedicated background thread that constantly monitors the Escape key:

  • Non-blocking Monitoring - The check_stop_thread function runs in parallel to the main program.
  • Emergency Stop - When ESC is pressed during playback, it sets the stop_current_song flag to True and releases all held keys.
  • Thread Safety - The thread uses a small sleep interval (0.1s) to prevent excessive CPU usage while maintaining responsiveness.

3. Main Program Flow

The main program follows this sequence:

  • Keymap Selection - Asks the user to choose between different keyboard layouts (Normal or Sky).
  • Folder Selection - Prompts for the song folder location, with an option to change from the default.
  • Song Loading - Scans the chosen directory for song files and loads them into memory.
  • Song Selection - Displays all available songs and lets the user choose one to play.
  • Playback Control - Handles the actual playing of notes with precise timing.

# 1. Setup and initialize import required libraries setup AHK interface initialize global variables # 2. Start background thread start ESC key monitoring thread # 3. Prepare for playback select_keymap() # Choose keyboard layout songs = load_songs_from_folder() # Load song files # 4. Input/Output System

SkyAutoMusic works by creating a bridge between stored song data and keyboard inputs:

Input: Song Files

  • JSON Format - Songs are stored as JSON files containing note timing and key information.
  • File Structure - Each song includes metadata (name, author, BPM) and an array of notes with specific timings.
  • Example Note - {"time": 1000, "key": "Key2"} means "play the Key2 note at 1000ms from the start".

Output: Keyboard Simulation

  • AHK Integration - The program uses the AutoHotkey library to simulate keyboard presses.
  • Key Mapping - The keys dictionary maps abstract notes (like "Key2") to actual keyboard keys (like "u").
  • Key Press Simulation - For each note, the program calls ahk_script.key_down(key) and schedules a release after the hold duration.

This architecture creates a flexible system that can easily adapt to different keyboard layouts and play complex songs with precise timing.

Octave System Explained

SkyAutoMusic supports multiple octaves to play a wider range of notes using the same physical keys:

How Octaves Work

  • Base Octave: Notes represented as "KeyX" (e.g., "Key0", "Key1")
  • First Octave: Notes represented as "1KeyX" (e.g., "1Key0", "1Key1")
  • Second Octave: Notes represented as "2KeyX" (e.g., "2Key0", "2Key1")

All three octaves map to the same physical keys on your keyboard. The prefixes are just identifiers that the song files use to indicate which note within which octave to play.

Example: Playing Across Octaves

In the song data, notes from different octaves might appear in sequence:

JSON - Notes Across Octaves
[ {"time": 0, "key": "1Key5"}, // Higher octave P key {"time": 500, "key": "Key2"}, // Middle octave U key {"time": 1000, "key": "2Key0"} // Lower octave T key ]

When playing this sequence, the program will press the "p" key, then "u", then "t", simulating a melody that spans multiple octaves while using the same physical keys.

Real-World Usage

This system provides several advantages:

  • Extended Range: Allows songs to use up to 45 different notes (15 keys × 3 octaves).
  • Consistent Layout: Players only need to learn one physical keyboard layout.
  • Flexible Notation: Song creators can specify notes in the most natural octave for reading.

How the Playback Engine Works

The heart of SkyAutoMusic is its playback engine, which handles the precise timing of when to press and release keys. Here's a detailed explanation of how it works:

Playback Initialization

Before playback begins, the program performs several setup steps:

  • Speed Factor Selection: Users can specify how fast the song should play (e.g., 1.0 = normal speed, 0.5 = half speed)
  • Starting Position: Users can choose to start from anywhere in the song (measured in minutes and seconds)
  • Timer Setup: A timer starts tracking elapsed time since the beginning of playback
  • Note Preparation: Notes are filtered to include only those after the chosen start position
Python - Playback Initialization
# Ask for speed factor speed_factor = float(input("Enter the speed factor: ")) # Ask for starting position start_position_input = input("Enter the starting position (e.g. '3m 15s' or '0'): ") if start_position_input.strip() == '0': start_position = 0 else: # Parse minutes and seconds start_position_minutes = int(start_position_input.split('m')[0].strip()) start_position_seconds = int(start_position_input.split('m')[1].split('s')[0].strip()) start_position = (start_position_minutes * 60 + start_position_seconds) * 1000 # Skip notes before the starting position song["songNotes"] = [note for note in song["songNotes"] if note["time"] >= start_position] # Start the playback timer start_timer = time.time() - (start_position / (1000 * speed_factor))

Timing and Synchronization

The playback engine uses sophisticated timing calculations to ensure notes play at exactly the right time:

Time Calculation

  • Real Time to Song Time: (time.time() - start_timer) * 1000 * speed_factor converts the elapsed real-world time to song time in milliseconds, adjusted for speed.
  • Release Timing: release_time = note_time + (key_hold_duration * 1000 / speed_factor) calculates when a key should be released after being pressed.
  • Pause Compensation: paused_time tracks how long the song has been paused to adjust the overall timing.

The Main Playback Loop

The core of the playback engine is a loop that:

  1. Groups notes by their timestamp to play simultaneous notes together
  2. Waits until the current elapsed time matches the timestamp of the next note group
  3. Handles pause/resume functionality when the spacebar is pressed
  4. Tracks which keys are being held down and when they should be released
  5. Updates the current playback position in real-time
Python - Main Playback Loop
# Group notes by time notes_by_time = {} for note in song["songNotes"]: if note["time"] not in notes_by_time: notes_by_time[note["time"]] = [] notes_by_time[note["time"]].append(note) # Track active notes and their release times active_notes = {} for note_time, notes in notes_by_time.items(): # Wait until it's time to play these notes while (time.time() - start_timer - paused_time) * 1000 * speed_factor < note_time: # Check for pause/resume (spacebar) if keyboard.is_pressed('space'): playing = not playing pause_start_time = time.time() time.sleep(0.2) # Release any keys that have reached their release time current_time = (time.time() - start_timer - paused_time) * 1000 * speed_factor keys_to_release = [] for key, release_time in active_notes.items(): if current_time >= release_time: ahk_script.key_up(key) keys_to_release.append(key) # Remove released keys from tracking for key in keys_to_release: active_notes.pop(key) # Display current playback position current_duration = current_time - start_position current_duration_minutes, current_duration_seconds = divmod(current_duration / 1000, 60) print(f"\rCurrent second: {int(current_duration_minutes)}m {int(current_duration_seconds)}s", end="") # Prevent CPU overload time.sleep(0.01) # Play all notes at the current timestamp for note in notes: key = keys.get(note["key"], note["key"]) ahk_script.key_down(key) release_time = note_time + (key_hold_duration * 1000 / speed_factor) active_notes[key] = release_time

Playback Control Features

The playback engine includes several features that give users control during playback:

Users can press the spacebar at any time to pause/resume playback:

2. Emergency Stop

3. Speed Control

Before playback starts, users can set the playback speed:

  • Examples: 1.0 = normal speed, 0.5 = half speed, 2.0 = double speed.

4. Real-time Progress Display

During playback, the current position in the song is displayed:

  • Time Formatting: Position is shown in minutes and seconds.
  • Real-time Updates: The display updates continuously as the song plays.

How Threading Works in SkyAutoMusic

SkyAutoMusic utilizes a multi-threaded architecture to handle both user input and playback simultaneously. This design allows the program to respond to user commands (like ESC to stop) even during intense playback sequences.

Thread Creation and Management

The program creates a separate background thread at startup for monitoring key presses:

Python - Thread Setup
# Function to check for stop key in background def check_stop_thread(): global playing_song, stop_current_song while True: if keyboard.is_pressed('esc') and playing_song: print("\nStopping playback and returning to song selection...") stop_current_song = True # Release all keys that might be held for key in keys.values(): ahk_script.key_up(key) time.sleep(0.5) # Prevent multiple triggers time.sleep(0.1) # Prevent excessive CPU usage # Start the stop checker thread stop_thread = threading.Thread(target=check_stop_thread, daemon=True) stop_thread.start()

Thread Coordination

The main and worker threads coordinate through shared variables and flags:

  • Global Flags: playing_song and stop_current_song are used for communication between threads.
  • Thread Safety: Simple boolean flags don't require locks because reads/writes are atomic in Python.
  • Daemon Mode: The worker thread is created with daemon=True, which means it will automatically terminate when the main program exits.

Thread Responsibilities

Main Thread:

The main thread is responsible for most of the program's functionality:

  • User Interface: Displays menus, song lists, and prompts for user input.
  • Song Selection: Handles the process of choosing songs and playback parameters.
  • File Loading: Reads and parses song files from the selected directory.
  • Note Playback: Manages the main playback loop for all notes in a song.
  • Pause/Resume: Handles the space key for pausing and resuming playback.

Background Worker Thread:

The worker thread has a more focused set of responsibilities:

  • Key Monitoring: Continuously checks if the ESC key has been pressed.
  • Emergency Stop: Sets the stop_current_song flag when ESC is detected during playback.
  • Key Release: Makes sure all keys are released when playback is stopped with ESC.

This separation of concerns ensures that the program remains responsive at all times, allowing users to stop playback instantly even if the main thread is busy with note scheduling or playback operations.

Benefits of Multi-threading

The threading model provides several key advantages:

1. Responsiveness

Without threading, the program would have to check for user input between note events, which could lead to delayed responses when the main thread is busy. With threading, the ESC key check runs continuously in the background, ensuring immediate response.

2. Clean Emergency Stops

When a user hits ESC to stop playback, the background thread can immediately release all held keys, preventing "stuck notes" that would continue to play indefinitely.

3. Simplified Main Loop

The main playback loop can focus solely on timing and note scheduling, without being cluttered with extra code for emergency stop detection.

4. Minimal Resource Usage

The worker thread uses time.sleep(0.1) to check for ESC presses 10 times per second, which keeps CPU usage low while still being responsive enough for user input.

Error Handling Strategies

SkyAutoMusic is designed to be robust and fault-tolerant, with comprehensive error handling throughout the codebase. Here's how errors are managed in different areas:

File Reading and Parsing

When loading song files, multiple layers of error handling ensure that problems with individual files don't crash the program:

  • Multi-Encoding Attempts: The program tries six different text encodings for each file before giving up.
  • JSON Parsing Errors: Invalid JSON is caught and reported, allowing the program to continue with other files.
  • File Access Issues: Problems with file permissions or missing files are handled gracefully.
  • Malformed Data: The program checks if loaded data has the expected structure before using it.

Runtime Error Management

During playback, various mechanisms prevent errors from disrupting the user experience:

When the program encounters an unknown note identifier, it uses a fallback mechanism:

This means that if a song file uses an unexpected note name, the program will try to use that name directly as a keyboard key rather than crashing.

User Input Validation

When collecting user input, the program validates the data and provides helpful feedback:

  • Keymap Selection: Loops until a valid choice (1 or 2) is provided.
  • Song Number: Checks that selected song numbers are within the valid range.
  • Starting Position: Handles various input formats for time specification.
  • Speed Factor: Converts input to float with appropriate error handling.

Emergency Recovery

The background thread provides a safety net for recovering from problems during playback:

  • Key Release: In case of errors, all currently pressed keys are released to prevent stuck notes.
  • State Reset: Global flags are reset to ensure the program can return to a clean state.
  • User Notification: Clear error messages explain what went wrong and what the user should do next.
